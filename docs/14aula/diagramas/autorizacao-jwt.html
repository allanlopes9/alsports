Aula 14 · Autorização

Autorização de uma requisição JWT

Autenticar responde quem é. Autorizar responde o que pode fazer. A cadeia abaixo mostra onde cada decisão acontece: validação do token, conversão do claim perfis, política HTTP e, por fim, @PreAuthorize no caso de uso.

Cadeia de decisão

1. BearerTokenAuthenticationFilterextrai o token do cabeçalho Authorization
2. JwtDecodervalida assinatura HS256, emissor e expiração
3. JwtAuthenticationConverterclaim perfis → authorities ROLE_*
4. AuthorizationFilteraplica a política HTTP na ordem declarada
5. @PreAuthorizerevalida o perfil no service (defesa em profundidade)
6. Controller / Serviceexecuta a regra de negócio ou responde 403

Simulador de política

Política HTTP implementada

requestMatchers(
    "/api/health",
    "/v3/api-docs/**",
    "/swagger-ui/**").permitAll()

requestMatchers(POST,
    "/api/autenticacao/login").permitAll()

requestMatchers(POST,
    "/api/contas-acesso")
    .hasRole("ADMINISTRADOR")

requestMatchers(
    "/api/contas-acesso/*/perfis",
    "/api/contas-acesso/*/status")
    .hasRole("ADMINISTRADOR")

requestMatchers(DELETE, "/api/**")
    .hasRole("ADMINISTRADOR")

requestMatchers("/api/**")
    .hasAnyRole("OPERADOR", "ADMINISTRADOR")

anyRequest().denyAll()

Como ler o resultado

200/201/204 · autorizado 401 · não autenticado 403 · autenticado sem permissão 400 · regra de negócio

A ordem importa: regras administrativas são declaradas antes de /api/**. Terminar com denyAll() impede que uma rota nova fique pública por esquecimento.

O @PreAuthorize("hasRole('ADMINISTRADOR')") também protege cadastrar, alterarPerfis e alterarStatus. Se a regra HTTP for alterada por engano, o service continua exigindo o perfil.
